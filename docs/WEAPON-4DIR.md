# v6.9 — 새 무기의 네 방향 공격 및 보행

기준은 사용자가 제공한 line2-clash-v6.8-claude.zip입니다. v5.7로 되돌린 것이 아닙니다.

## 해결한 제한
가방·소화기·야구방망이의 남녀 각각에 독립 정면/오른쪽/후면/왼쪽 공격과 무기를 든 보행 원화를 추가하고 게임에 연결했습니다. 남자 넓은 훅도 네 방향입니다. 좌우 UV 반전과 위/아래에 옆모습을 재사용하던 경로는 제거했습니다. 보행/대기 중에도 선택 무기가 계속 보입니다. 대각선은 기존처럼 가까운4방향 자세를 사용합니다.

여자 풍차는 기존 hero-female 원화,12fps,기존기본0.36초/간격0.42초와 장갑 보정을 유지합니다. 새 고속풍차나 복싱 잽으로 바꾸지 않았습니다. 장우산의 기존4방향 공격/보행은 유지했습니다.

## 유지한 v6.8 시스템
아이템 가격·시간·타격위력·범위·중복 구매시간 추가·교체는 변경하지 않았습니다. 가방20원/90초/120도, 우산40원/120초/90도, 소화기90원/100초/90도, 방망이180원/120초/90도. 스킬/보스/미션/튜토리얼/소리/아이콘/시작화면/visualViewport 대응/세이브키와 보호 규칙을 유지합니다. 기존 여자를 원래 풍차로 유지하는 성별 구분도 유지합니다.

## 자산과 크기
새 시트13장 ×32프레임=416프레임. 각 시트8열4행,게임용1536×640(셀192×160),원화는 assets/original의 동명PNG. 행 순서 front/right/back/left입니다. aspect1.2,게임 sprite3.06×2.55,발기준셀Y152/160와 기존 sprite.center.y=.052를 맞춥니다. 어깨/팔/물건 전체가 셀 안에 들어갑니다. 머리에서 발까지의 길이를 기준으로 공통 크기를 잡아 무기를 들 때 몸이 작아지는 것도 줄였습니다.

이미지는 원본 전체 연결 성분에서 추출해 정해진 칸 경계를 넘는 팔/무기를 잃지 않습니다. PNG 전체416프레임에서 최소6픽셀 투명 여백을 확인했고, docs/WEAPON-FRAME-SAFETY.json에 근거가 있습니다. WebP95로 내장하고 기존 단계적 GPU 사전 로딩을 유지했습니다. 사용하지 않는 이전 한 시점 attacks-* 3개는 원본파일은 보존하되 게임 로드목록에서 제외했습니다. 현재 게임 로드자산38개,게임HTML약9.5MB입니다.

## 실행
- game/index.html: 실제 게임
- preview/weapons.html:13종의4방향 보행/공격을 동시에 확인,정지/프레임/속도 선택
- npm install / npm test / npm run build / npm start
- npm run pack:weapons / npm run preview:weapons: 새 자산 및 확인 화면 재생성

## 검증 및 한계
기존 전체 자동 검사를 통과했습니다. 새검사는 남녀3종의 무기를 든 보행/정지,독립4방향 공격/훅,모든416프레임,여자원본/12fps,프레임 UV 및 크기를 확인합니다. 844×390,740×290,932×430의 가로화면에서 객차양끝×벽쪽위치4개와 흔들림 오프셋을 조합하여 실제 그림의 경계39936점을 투영해 화면 내인지 확인했습니다. 원본 분리 및 여백 검사와 소프트웨어 렌더도 수행했습니다.

실제 브라우저 GPU 화면 캡처·실제 휴대폰 입력/성능·소리 청취는 미검증입니다. 소프트웨어 계산 검사를 실기 검증으로 보고하지 마세요. 4방향 스프라이트이며 8방향 독립원화나 자유회전3D가 아닙니다.

## 강한 흔들림에서의 화면 보호
keepWeaponInView는 현재 무기를 든/휘두르는 그림 전체가 화면에서12픽셀 이내로 접근할 때만 카메라를 최소 보정합니다. 일반 추적과 흔들림은 그대로 두며, 보정값은 camOff에 함께 기록해 다음 프레임에 누적되지 않게 합니다. 재사용 벡터를 사용하고 새 재질이나 DOM 크기 측정을 만들지 않습니다. 3개 가로화면×4개 큰 킥/롤 조합(±1.8 이동·±0.08rad 기울기)의12경우에서도 전체 스프라이트가12픽셀 여백 안에 들어가며 보정이 반복 누적되지 않음을 검사했습니다.
